# Smart Fitness AI

## หน้าเตรียมข้อมูลเทรน AI
หน้าใหม่แบ่งเป็น 3 แท็บ: **ตรวจและติดป้าย**, **เพิ่มคลิป**, **ส่งออกและเทรน**
การตั้งค่าการแตกภาพและวิดีโอต้นฉบับพับเก็บได้ เพื่อให้เห็นภาพที่กำลังตรวจชัดเจน
รายภาพแสดงครั้งละ 6 ภาพ พร้อมจำนวนทั้งหมด ความคืบหน้า และช่วงเวลาของหน้าปัจจุบัน
ใช้ช่องเลือกหน้าด้านบน หรือปุ่ม **หน้าก่อน / หน้าถัดไป** ใต้ภาพ และบันทึกป้ายก่อนเปลี่ยนหน้า
ชื่อป้ายในหน้าจอเป็นภาษาไทย แต่ค่า class ใน CSV ยังเหมือนเดิม

## ติดป้ายรายภาพพร้อม Pose Landmarks

เปิดแอปด้วยคำสั่งเดิม แล้วเข้า **นำเข้าวิดีโอ / ติดป้ายกำกับ**:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

1. นำเข้าหรือเลือกคลิป แล้วเลือก **ติดป้ายรายภาพ**
2. เลือกท่าของคลิป และตั้ง **ดึงภาพทุกกี่วินาที** ค่าเริ่มต้น 1 วินาที
   คลิป 60 วินาทีที่มี timestamps ปกติจะได้ประมาณ 60 ภาพ
   ท่าที่เคลื่อนไหวเร็วเลือก 0.2 หรือ 0.5 วินาทีได้
3. กด **แตกภาพและตรวจจับข้อต่อ** ระบบใช้ MediaPipe และ EMA กับเฟรมตามลำดับ
   ก่อนเก็บเฉพาะภาพตามความถี่ที่เลือก จึงไม่ต้องวาดกรอบคนเอง
4. ดูภาพครั้งละ 6 ภาพ เปลี่ยนหน้าได้ เปิด–ปิด Skeleton และหมายเลขจุดข้อต่อได้
   สีเส้นหมายถึงจุดที่ตรวจพบ ไม่ใช่คำตัดสินว่าท่าถูกหรือผิด
5. ติ๊กภาพหนึ่งภาพหรือหลายภาพในหน้าปัจจุบัน เลือกคลาส แล้วกด **บันทึกป้ายภาพที่เลือก**
   ป้ายบันทึกลงดิสก์ทันที เปลี่ยนหน้าภาพหลังบันทึกแล้วจึงไม่เสียตัวเลือกที่ยังไม่ได้บันทึก
   เลือก **ข้ามภาพ** สำหรับภาพเปลี่ยนท่า/เบลอ/ตรวจข้อต่อผิด หรือ **ล้างป้าย** เพื่อกลับมาตรวจใหม่
   ภาพที่ไม่มีข้อต่อครบจะไม่อนุญาตให้บันทึกเป็นคลาสฝึก แต่เลือกข้ามได้
6. กด **แปลงคลิปทั้งหมดเป็น CSV** จะส่งออกเฉพาะภาพที่มีป้ายคลาสแล้ว
   ภาพที่ข้ามและยังไม่ติดป้ายจะไม่เข้า CSV จากนั้นเทรนด้วยคำสั่งเดิม:

```powershell
.\.venv\Scripts\python.exe 2_train_model.py --data dataset/video_pose_data.csv --model rf
```

หนึ่งคลิปส่งออกจากโหมดที่เลือกเท่านั้น: **รายภาพ** หรือ **ช่วงเวลา** จึงไม่ส่งข้อมูลซ้ำสองแบบ
ป้ายอีกโหมดยังเก็บไว้ กลับไปเลือกใช้ได้ รายภาพใช้พิกัดและ features ที่สร้างพร้อมภาพตรวจทาน
ไม่ใช้ภาพ JPEG ที่วาดเส้นเป็น input ของ classifier และไม่ต้องรัน MediaPipe ซ้ำตอนส่งออกรายภาพ
Subject ID และรอบการถ่ายยังใช้จัดกลุ่ม Train/Test เหมือนเดิม

ภาพ JPEG เก็บใน `dataset/video_project/frames/` ส่วนป้ายและพิกัดอยู่ใน `annotations.json`
สำรองทั้ง `video_project` เพื่อทำงานต่อบนเครื่องอื่น หากสร้างชุดภาพใหม่ต้องยืนยันก่อน
เพราะป้ายรายภาพเดิมจะถูกแทนที่ (ป้ายช่วงเวลาไม่ถูกลบ)
หากเปลี่ยนแนวหมุนภาพหลังสร้างชุด ต้องสร้างชุดใหม่และตรวจป้ายใหม่ก่อนส่งออก
โฟลเดอร์ภาพจากการสร้างรอบเก่ายังคงอยู่บนดิสก์ จึงใช้พื้นที่เพิ่มเมื่อสร้างซ้ำ
เครื่องมือนี้ยังเป็นเวอร์ชันใช้บนคอม ไม่ได้เพิ่มระบบบัญชีหรือ deployment ออนไลน์

เว็บแอป Python / Streamlit ตรวจจับ 33 landmarks ด้วย MediaPipe Pose, ลดการสั่นด้วย EMA,
ใช้ **โมเดล Scikit-learn ที่เทรนจากข้อมูลของคุณ** ร่วมกับกฎมุม/ระยะ และ FSM สำหรับ 4 ท่า
ธีม Dark Teal / Mint Green พร้อม Choose → Train → Review

## 1. ติดตั้งและเปิดแอป (Windows PowerShell)

ใช้ **Python 3.10–3.12 แบบ 64-bit** แนะนำ 3.12 และรันจากโฟลเดอร์โปรเจกต์:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

เปิด `http://localhost:8501` บนเครื่องที่รันเซิร์ฟเวอร์ ไม่จำเป็นต้อง activate venv
หากยังไม่มีโมเดล ให้เลือก **ทดสอบด้วยกฎอย่างเดียว** เพื่อเช็กกล้องก่อน
แอปจะไม่แอบแทนที่ Custom AI ด้วยข้อมูลหรือโมเดลจำลอง

MediaPipe ถูกตรึงเป็น 0.10.21 เพื่อใช้ `mp.solutions.pose`; OpenCV ใช้แพ็กเกจ
`opencv-contrib-python` ซึ่งมี `cv2` และ VideoCapture ครบแล้ว **อย่าติดตั้ง OpenCV
หลายแพ็กเกจทับกัน** (เช่น opencv-python / headless) ใน venv นี้

## 2. เก็บข้อมูลจริง

```powershell
# Webcam ของเครื่องนี้
.\.venv\Scripts\python.exe 1_collect_data.py --source 0 --subject person01

# DroidCam: แทนที่ด้วย URL ของมือถือจริง
.\.venv\Scripts\python.exe 1_collect_data.py --source "http://192.168.1.10:4747/video" --subject person01
```

สคริปต์เปิดหน้าต่าง OpenCV บนเครื่องที่รัน ต้องคลิกหน้าต่างก่อนกดปุ่ม:

| ปุ่ม | คลาส |
|---|---|
| 1 | squat_up |
| 2 | squat_down_correct |
| 3 | squat_down_wrong |
| 4 | pushup_up |
| 5 | pushup_down_correct |
| 6 | pushup_down_wrong |
| 7 | plank_correct |
| 8 | plank_wrong |
| 9 | jj_closed |
| 0 | jj_open_correct |
| j | jj_open_wrong |

- **Space** เริ่ม/พักบันทึก โดยค่าเริ่มต้นเป็นพัก
- เปลี่ยนคลาสแล้วระบบพักอัตโนมัติ จัดท่าให้พร้อมก่อนกด Space
- **n** เริ่ม recording group ใหม่และพักบันทึก
- **q / Esc** จบและคืนกล้อง
- เก็บเริ่มต้น 5 ตัวอย่าง/วินาที ปรับด้วย `--sample-fps 5`

ไฟล์ `dataset/pose_data.csv` สร้างอัตโนมัติและเพิ่มแถวต่อท้าย มี schema version,
session_id, subject_id, timestamp, label, พิกัด raw x/y/z/visibility ทั้ง 33 จุด,
พิกัดผ่าน EMA ที่ normalize เทียบจุดกลางสะโพกและความยาวลำตัว รวมถึงมุมและระยะข้อเท้า/ไหล่
ไม่บันทึกภาพหรือวิดีโอ และไม่บันทึกเฟรมที่ไม่เห็นข้อต่อสำคัญ

ควรเก็บอย่างน้อย 100–300 ตัวอย่างต่อคลาสจากหลายรอบและหลายคน ทุกคลาสต้องอยู่ใน
อย่างน้อย 2 recording groups ที่เป็นการถ่ายคนละรอบจริง แนะนำ 4 รอบขึ้นไป
แต่ละรอบควรมีครบ 11 คลาส เปลี่ยนระยะ/แสง/เสื้อผ้า และบันทึกท่าผิดตามป้ายกำกับจริง
อย่ากด n ซ้ำขณะค้างท่าเดิมเพื่อแบ่งเฟรมที่เหมือนกันเป็นคนละกลุ่ม
จำนวนขั้นต่ำที่โปรแกรมรับคือ 10 ตัวอย่าง/คลาส แต่ไม่ได้แปลว่าเพียงพอต่อความแม่นยำ

## 3. เทรน Custom Model

**ถ้าอัดคลิปไว้ก่อน:** ใช้หน้า **นำเข้าวิดีโอ / ติดป้ายกำกับ** ใน Sidebar
ตามวิธีด้านล่าง แล้วเทรนด้วย `--data dataset/video_pose_data.csv`

```powershell
# Random Forest (ค่าเริ่มต้น)
.\.venv\Scripts\python.exe 2_train_model.py --model rf

# MLPClassifier เป็นอีกทางเลือก จะเขียนทับโมเดลเดิม
.\.venv\Scripts\python.exe 2_train_model.py --model mlp --max-iter 500

# ประเมินกับคนที่โมเดลไม่เคยเห็น ต้องมีหลาย subject และครบคลาสทั้งสองฝั่ง
.\.venv\Scripts\python.exe 2_train_model.py --group-by subject_id
```

Pipeline ประกอบด้วย StandardScaler + classifier โดย fit scaler เฉพาะ Train
แบ่ง Train/Test ตาม `session_id` (หรือ `subject_id`) ด้วย GroupShuffleSplit
เพื่อไม่ให้เฟรมข้างเคียงจากการถ่ายรอบเดียวกันปะปนสองชุด
ค้นหา split ที่ครบคลาสทั้งสองฝั่งโดยไม่เลือกจากคะแนน Test
หากข้อมูลไม่พอจะแจ้งให้เก็บเพิ่ม ไม่ fallback ไปสุ่มเฟรม
Test ใช้ประเมินเท่านั้น โมเดลที่บันทึกเป็นตัวเดียวกับที่ประเมิน

ผลลัพธ์:

- แสดง Accuracy และ Classification Report (precision / recall / F1) ใน terminal
- `models/fitness_model.pkl`: Pipeline + schema/features + metadata
- `models/confusion_matrix.png`: กราฟ confusion matrix
- `models/training_metrics.json`: รายงานและรายชื่อ Train/Test groups

ถ้าเลือก MLP แล้วมี ConvergenceWarning ให้พิจารณาการกระจายข้อมูลหรือเพิ่ม max-iter
อย่าเลือกโมเดลซ้ำ ๆ จาก Test เดิมจนคะแนนกลายเป็นผลจากการปรับเข้าหาชุด Test
เมื่อมีครบคลาสของท่าที่เลือก แอปจะยอมให้เริ่ม Custom AI mode; หากขาดจะแจ้งชื่อคลาส
โหลดเฉพาะ `.pkl` ที่คุณเทรนและเชื่อถือ เพราะ Joblib สามารถรันโค้ดขณะ deserialize ได้

## 4. กล้องสองรูปแบบ

### มือถือผ่าน Browser / WebRTC

1. เปิดแอปจากเบราว์เซอร์ของอุปกรณ์ที่มีกล้อง
2. เลือก **มือถือ / Browser (WebRTC)** → ท่า → เริ่มเซสชันใหม่
3. กด START ที่วิดีโอ แล้วอนุญาตกล้อง
4. กด **จบเซสชันและดูสรุป** เมื่อต้องการสิ้นสุดการฝึก

`localhost` ใช้กล้องได้บนเครื่องนั้น แต่การเปิด `http://192.168.x.x:8501`
จากมือถืออีกเครื่องโดยทั่วไปใช้ getUserMedia ไม่ได้ ต้องจัด **HTTPS ที่เบราว์เซอร์เชื่อถือ**
ผ่าน reverse proxy / tunnel หรือเซิร์ฟเวอร์ HTTPS และให้มือถือเข้าถึงเซิร์ฟเวอร์ได้
การเชื่อมต่อข้าม NAT บางเครือข่ายต้องใช้ TURN; ตั้งค่าของผู้ให้บริการก่อนเปิดแอป:

```powershell
$env:TURN_URL = "turn:your-turn-server:3478"
$env:TURN_USERNAME = "your-username"
$env:TURN_PASSWORD = "your-password"
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 0.0.0.0
```

TURN ไม่จำเป็นสำหรับทุกเครือข่าย และการ bind 0.0.0.0 ไม่ได้ทำให้เป็น HTTPS
ภาพจากเบราว์เซอร์ถูกส่งไปประมวลผลบนเซิร์ฟเวอร์ Streamlit
หากกด STOP ของ WebRTC ให้จบเซสชัน แล้วเริ่มเซสชันใหม่เมื่อต้องการฝึกอีกครั้ง

### DroidCam / IP Camera / Webcam ผ่าน OpenCV

เลือกโหมดที่สองแล้วกรอก `0`, `1` หรือ URL เช่น `http://192.168.1.10:4747/video`
**index หมายถึงกล้องที่ต่อกับเครื่องเซิร์ฟเวอร์** ไม่ใช่มือถือที่เปิดหน้าเว็บ
URL ต้องส่งวิดีโอที่ FFmpeg/OpenCV อ่านได้และเข้าถึงจากเซิร์ฟเวอร์ได้
DroidCam แต่ละเวอร์ชันอาจใช้ URL/พอร์ตต่างกัน ให้ใช้ที่แอป DroidCam แสดง
ปิดโปรแกรมเก็บข้อมูลหรือโปรแกรมอื่นที่ใช้กล้องก่อนเปิดโหมดฝึก

Capture ทำงานใน background thread และส่งภาพล่าสุดให้ UI ด้วย `st.fragment`
มี timeout สำหรับ network stream และคืนกล้องเมื่อจบเซสชัน/เกิดข้อผิดพลาด
หากปิดหน้าเว็บ worker จะหยุดเมื่อไม่มี heartbeat ประมาณ 15 วินาที
ไดรเวอร์ Webcam บางตัวอาจบล็อก `read()` เกิน timeout ได้

## 5. กฎการนับและการประเมิน

| ท่า | วงจร / เกณฑ์ |
|---|---|
| Squat | ยืน (เข่า ≥160°) → ย่อ (≤110°) → ยืน; ท่าถูกต้องเมื่อเข่าที่ต่ำสุด 70–100° และแนวหลัง >150° |
| Push-up | เหยียดศอก ≥160° → ลดตัว ≤110° → เหยียด; จุดต่ำสุด 65–100° และลำตัว ≥160° ในแนวขนานพื้น |
| Plank | บวกเวลาระหว่างเฟรมที่ถูกต้องต่อเนื่องเท่านั้น: Shoulder–Hip–Ankle 160–180° และลำตัวขนานพื้น |
| Jumping Jacks | ชิดเท้า/แขนลง → กาง → กลับชิด; ไหล่ทั้งสอง Hip–Shoulder–Wrist >140°, ข้อมือทั้งสองสูงกว่าจมูกซึ่งใช้แทนระดับศีรษะ, ระยะข้อเท้า/ไหล่ >1 |

มุม “หลัง” ใช้ **Ear–Shoulder–Hip** เป็นตัวแทนแนวคอและลำตัวส่วนบน เนื่องจาก MediaPipe
ไม่มีจุดกลางกระดูกสันหลัง; แยกจากมุม Shoulder–Hip–Knee ซึ่งเปลี่ยนเมื่อพับสะโพกใน Squat
นี่เป็นเกณฑ์เรขาคณิตสำหรับโปรเจกต์ ต้องตรวจเทียบกับภาพที่ติดป้ายกำกับของคุณ
มุมทั้งหมดคำนวณในระนาบภาพหลังแก้อัตราส่วน width/height ไม่ใช่มุม 3D ที่วัดจริง
ควรตั้งกล้องระดับลำตัว ด้านข้างสำหรับ 3 ท่าแรก ด้านหน้าสำหรับ Jumping Jacks

- ใช้ EMA alpha=0.45 เหมือนกันตอนเก็บและใช้งานจริง
- FSM ยืนยันตำแหน่งปลายทางอย่างน้อย 120 ms จึงเปลี่ยนสถานะ
- เริ่มจากท่าย่อ/ท่ากางจะยังไม่นับจนเริ่มวงจรใหม่จากท่าตั้งต้น
- **จำนวนครั้งทั้งหมด** นับวงจรการเคลื่อนไหว ส่วน **ครั้งที่ท่าถูกต้อง** ตรวจคุณภาพด้วย
- Jumping Jacks กางบางส่วนอาจนับเป็นครั้งที่ผิด แต่ต้องเคยกางครบเงื่อนไขจึงเป็นครั้งที่ถูก
- AI ต้องมั่นใจ ≥threshold และเป็น exercise เดียวกันจึงเดิน FSM;
  คลาส `_wrong` ทำให้คุณภาพไม่ผ่าน แต่ยังนับการทำครบวงจรเป็นครั้งที่ผิดได้
- สีเขียวต้องผ่านทั้งกฎและ AI; สีแดงและข้อความไทยแสดงเมื่อไม่ผ่าน
- Plank ไม่บวกเวลาจากเฟรมผิด/เฟรมหาย/ช่วงภาพขาดเกิน 0.5 วินาที และไม่ให้คนยืนตรงนับเป็น Plank
- **Form Score** คือสัดส่วนเงื่อนไขที่ผ่านในแต่ละเฟรม รวมเงื่อนไข AI เมื่อใช้โมเดล
  แล้วเฉลี่ยเฟรมที่เห็นท่าชัดเจน ไม่ใช่ probability หรือ Accuracy ของโมเดล
  จึงอาจลดลงระหว่างเปลี่ยนท่าแม้สุดท้ายทำครบหนึ่งครั้งที่ถูกต้อง
- Review มีกราฟและดาวน์โหลด CSV; กราฟเก็บ 18,000 จุดล่าสุด (สูงสุดประมาณ 10 จุด/วินาที)
  ส่วนคะแนนเฉลี่ย/ตัวนับเป็นผลสะสมทั้งเซสชัน ไม่มีการเก็บผลข้ามการปิดเซิร์ฟเวอร์โดยอัตโนมัติ

## นำคลิปที่อัดไว้มาเทรน (ทำภายหลังได้ ไม่ต้องต่อกล้อง)

เปิดแอปด้วยคำสั่งเดิม:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

1. คลิก **นำเข้าวิดีโอ / ติดป้ายกำกับ** ใน Sidebar หากมีเซสชันฝึกอยู่ให้จบก่อน
2. เลือกคลิป MP4 / MOV / M4V / AVI / MKV / WebM ได้หลายไฟล์พร้อมกัน
   หรือกรอกพาธไฟล์บนคอมที่รัน Streamlit สำหรับคลิปใหญ่ โดยไม่ต้องอัปโหลดผ่านเบราว์เซอร์
   การอัปโหลดใช้ขีดจำกัด Streamlit เริ่มต้น 200 MB ต่อไฟล์
3. กรอก **Subject ID** เช่น `person01` และ **รอบการถ่าย** เช่น `take01`
   คลิปทุกท่าที่ถ่ายในรอบเดียวกันใช้รอบเดียวกัน เปลี่ยนเป็น `take02` เมื่อถ่ายรอบใหม่จริง
   ทั้งสองค่านี้ใช้สร้าง session_id ให้คลิปจากรอบเดียวกันอยู่ฝั่งเดียวกันตอนแบ่ง Train/Test
4. กด **นำเข้าและบันทึกคลิป** ระบบคัดลอกต้นฉบับเข้า `dataset/video_project/videos/`
   และตรวจ SHA256 เพื่อไม่ให้นำเข้าไฟล์เดิมซ้ำแม้เปลี่ยนชื่อไฟล์
5. เลือกคลิป ดูวิดีโอ หรือกรอกเวลาแล้วกด **แสดงเฟรม ณ เวลาที่เลือก**
   ระบบอ่าน timestamps จริง รองรับเฟรมเรตไม่คงที่จากมือถือ
   ภาพเฟรมจะหมุนตาม metadata อัตโนมัติ ถ้ายังเอียงให้แก้ในเมนูแนวภาพ
   การหมุนเพิ่มมีผลต่อภาพเฟรมและข้อมูลฝึก ส่วน video player แสดงต้นฉบับตามเบราว์เซอร์
6. เลือกท่า กรอกเวลาเริ่ม/จบเป็นวินาที เลือกคลาส แล้วกด **เพิ่มช่วงและบันทึกป้ายกำกับ**
   เช่น `2.0–4.5: squat_up`, `7.0–9.0: squat_down_correct`
   ช่วงเวลาเป็น `[เริ่ม, จบ)` ไม่รวมเฟรมตรงเวลาจบ ช่วงติดกันได้แต่ทับกันไม่ได้
7. ใช้เมนู **แก้ไขหรือลบช่วงที่บันทึกแล้ว** เพื่อเปลี่ยนเวลา/คลาส หรือลบเฉพาะป้ายกำกับ
   ไม่ลบวิดีโอต้นฉบับ ป้ายกำกับบันทึกลงดิสก์ทุกครั้ง ปิดเว็บ/ปิดคอมแล้วกลับมาทำต่อได้
8. กด **แปลงคลิปทั้งหมดเป็น CSV** ค่าเริ่มต้นเก็บสูงสุด 5 ตัวอย่าง/วินาที
   โปรแกรมประมวลผลทุกเฟรมในช่วงที่ติดป้ายเพื่อให้ EMA ต่อเนื่อง แล้วลดเฉพาะอัตราการบันทึก CSV
   ข้ามเฟรมที่เห็นข้อต่อไม่ครบ พร้อมแสดงจำนวน saved/skipped แยกแต่ละช่วง
9. เทรนจากไฟล์ที่ได้:

```powershell
.\.venv\Scripts\python.exe 2_train_model.py --data dataset/video_pose_data.csv --model rf
# หรือ
.\.venv\Scripts\python.exe 2_train_model.py --data dataset/video_pose_data.csv --model mlp
```

**เลือกเฉพาะช่วงที่เป็นสถานะนั้นจริง** ไม่ติดป้าย `squat_up` ให้ทั้งคลิปที่มีทั้งยืนและย่อ
ช่วงเปลี่ยนท่าที่ไม่ติดป้ายจะไม่ถูกส่งออก ไม่จำเป็นต้องตัดวิดีโอเป็นไฟล์ย่อยเอง
ท่าผิดต้องติดป้ายจากสิ่งที่อยู่ในภาพจริง ระบบไม่ใช้โมเดลหรือกฎมาสร้างคำตอบแทนผู้ติดป้าย
คลิปไว้ทดสอบระบบนับแบบต่อเนื่องสามารถนำเข้าแต่เว้นไม่ติดป้าย เพื่อไม่รวมในชุดเทรน

ไฟล์ที่ได้:

- `dataset/video_project/annotations.json` — ข้อมูลคลิป ผู้ถ่าย รอบการถ่าย และช่วงเวลาพร้อมป้าย
- `dataset/video_project/videos/` — สำเนาคลิปต้นฉบับ สำรองทั้งโฟลเดอร์ `video_project` เพื่อย้ายเครื่อง
- `dataset/video_pose_data.csv` — schema เดียวกับการเก็บจากกล้องสด ใช้เทรนได้ทันทีเมื่อข้อมูลครบ
- `dataset/video_pose_data.report.json` — รายงานการส่งออกและที่มาของแต่ละช่วง

ส่งออกซ้ำจะ **สร้าง CSV ใหม่ทั้งชุดแทนไฟล์ส่งออกเดิม** ไม่ต่อแถวซ้ำ
ไม่แก้ `dataset/pose_data.csv` จากกล้องสด ถ้าส่งออกแล้วพบว่าไม่มีเฟรมใช้ได้ หรืออ่านคลิปไม่สำเร็จ
จะคง CSV เดิมไว้ หลังแก้ป้ายกำกับต้องส่งออกใหม่ก่อนเทรน
คอลัมน์ timestamp ของข้อมูลวิดีโอเป็น `video:<SHA256>:<วินาที>s` สำหรับตามกลับไปยังเฟรมต้นฉบับ
ไม่ใช่วันที่ถ่ายคลิป ส่วน session_id คงเดิมเมื่อส่งออกซ้ำ

ควรให้แต่ละคลาสมีข้อมูลจากอย่างน้อย 2 รอบอิสระ แนะนำ 4 รอบขึ้นไปพร้อมครบคลาสในแต่ละรอบ
ตารางบนหน้าแอปบอกจำนวนรอบและเวลาที่ติดป้ายแล้ว ส่วนจำนวนแถวใช้ได้จริงดูหลังส่งออก
การอัปโหลดหลายคลิปจากรอบเดียวกันยังนับเป็นเพียงหนึ่งกลุ่มสำหรับแบ่ง Train/Test

ส่งออกผ่าน terminal จากป้ายกำกับที่บันทึกไว้แล้วได้เช่นกัน:

```powershell
.\.venv\Scripts\python.exe 1_import_videos.py --sample-fps 5
```

MOV/HEVC บางแบบอาจเล่นในเบราว์เซอร์ไม่ได้แม้ถอดรหัสเฟรมได้ ให้ใช้ภาพเฟรมช่วยติดป้าย
หรือแปลงไฟล์เป็น MP4 H.264 ก่อนนำเข้า หาก decoder อ่านไม่ได้จะแจ้งข้อผิดพลาด
ระหว่างส่งออกให้รอจนเสร็จก่อนปิดหน้าเว็บ; annotation ที่บันทึกไว้แล้วไม่สูญหาย
หากโปรแกรมถูกบังคับปิดแล้วแจ้งว่าโปรเจกต์กำลังทำงาน ให้ปิดโปรแกรมนำเข้า/ส่งออกทุกตัวก่อน
